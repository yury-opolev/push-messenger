# push-messenger — Implementation Roadmap

Spec: `docs/superpowers/specs/2026-10-11-push-messenger-design.md`

The spec covers several independent subsystems, so it is delivered as a sequence of
plans. Each plan produces working, tested software on its own and is written in full
detail just before it is executed, so it can use what earlier plans actually produced.

| # | Plan | Delivers | Depends on |
|---|---|---|---|
| 1 | **Messaging core** | `push-domain`: contacts, direct conversations, send with gapless `seq` and idempotent retry, sync and cumulative ack, read positions, history — over storage traits with an in-memory store | — |
| 2 | Core extensions | Edit and delete with erasure, invites, groups up to 100 with admin/member roles and visibility ranges, unread counts | 1 |
| 3 | Postgres store | `push-store`: migrations and the storage traits on Postgres (sqlx); integration tests on testcontainers, including concurrent retries | 1, 2 |
| 4 | Auth service | `push-auth`: signup, stateless email links, login, explicit device registration, JWT and refresh rotation, handles, profiles, JWKS, outbox | 3 |
| 5 | Worker and email | `push-worker`, `push-email`: outbox relay, Resend sender, webhooks, suppression list, cleanup jobs | 3, 4 |
| 6 | Message service | `push-proto` wire and gRPC definitions; `push-message-svc` exposing the core over gRPC; Redis notify and kick | 2, 3 |
| 7 | Gateway | `push-gateway`: WebSocket termination, local JWT checks, frames, Identify/ReAuth, heartbeats, close codes, draining | 6 |
| 8 | SDK core | `push-sdk`: connection state machine, SQLite outbox, local store, retries, events | 7 |
| 9 | SDK bindings | napi-rs Node binding, cbindgen C binding | 8 |
| 10 | Deployment | Helm chart, k3s provisioning, CI, end-to-end and 10k-connection load tests | 4–8 |
