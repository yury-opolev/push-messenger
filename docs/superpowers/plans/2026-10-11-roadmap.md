# push-messenger — Implementation Roadmap

Spec: `docs/superpowers/specs/2026-10-11-push-messenger-design.md`

The spec covers several independent subsystems, so it is delivered as a sequence of
plans. Each plan produces working, tested software on its own and is written in full
detail just before it is executed, so it can use what earlier plans actually produced.

## Running locally on minikube

The whole system must run on a local minikube cluster, using the same Helm chart that
deploys to Azure. This is introduced early, as a walking skeleton right after the
Postgres store, rather than at the end. From then on **every plan is verified on
minikube** before its pull request is merged, so Kubernetes problems (probes, ingress
WebSocket upgrade, timeouts, service wiring, secrets) surface while they are small.

Locally, email uses the log-only sender, so no cloud account is needed to run the system.
