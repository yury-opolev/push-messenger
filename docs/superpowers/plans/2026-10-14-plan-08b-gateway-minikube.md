# Plan 8B — Gateway: minikube Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove Plan 8A end to end on the local minikube cluster with the same chart that will deploy to Azure, the way a client app uses the system. The smoke test talks only to auth-svc's public API and the gateway's WebSocket, through the ingress, with real access tokens: three users connect (the gateway answers 4006 until the worker has relayed a device), become contacts by request and by invite, chat, edit, read and delete over the WebSocket, see a group request refused, see only the profiles they may see, see an expired token and a token for another audience refused, and finally see a revoked device and a password reset close their sockets with 4003 and 4001 and their old tokens refused. message-svc's `Messaging` API, which acts for whatever user and device it is given, takes calls only with the gateway's own internal token, generated by the chart. `test-chart.ps1` has 31 checks.

**Architecture:** The smoke test drops its gRPC client of message-svc (`messaging.rs`) and its Redis listener (`kicks.rs`); a new `socket.rs` holds a connection as an app does — identified with the device's token, frames sent and awaited in order, frames that arrive while waiting for another kept — and a new `tokens.rs` signs the two tokens the gateway must refuse with auth-svc's own key and key id, so that only the claim under test is wrong. In message-svc, `InternalToken::messaging` guards `Messaging` as the worker's and auth-svc's tokens guard `Accounts` and `Directory`; the gateway puts the bearer token on every call through a tonic interceptor. In the chart the Secret gets `messaging-token` (48 random characters, generated once and kept with `lookup`), given to the gateway and message-svc only; the smoke Pod loses `--message-svc` and the Redis URL and gets `PUSH_SMOKE_SIGNING_KEY` from the Secret's `auth-signing-key`. No database or script changes: message-svc's migration 0003 and the new Secret key arrive on the upgrade. Spec: `docs/superpowers/specs/2026-10-11-push-messenger-design.md` §2, §7, §11, §12; roadmap "Running locally on minikube".

**Tech Stack:** Docker (BuildKit), minikube 1.34 (Kubernetes 1.31, docker driver, ingress addon), kubectl, Helm 3.16, PowerShell 7 and bash. `push-smoke` now uses `base64` 0.22 (in the workspace) and no longer `redis`, `tonic` or `prost`.

## Key rules the configuration must preserve

- **One token per internal API, given only to its caller.** `accounts-token` reaches
  message-svc and the worker, `directory-token` message-svc and auth-svc, and
  `messaging-token` message-svc and the gateway. All three are generated on install, kept
  on upgrades (`lookup`), must differ (message-svc refuses to start otherwise) and reach
  containers only through `secretKeyRef`.
- **No secret in git, in a ConfigMap or in a Pod's arguments.** The smoke test reads
  auth-svc's signing key from the Secret through its environment and never prints it or the
  tokens it signs (`Target`'s `Debug` redacts it).
- **The smoke test is a client.** It reaches auth-svc and the gateway only through the
  ingress, like an app; only the DEV ONLY mailbox is read from the worker directly.
- **The smoke test never prints bodies, tokens, invite codes or token-bearing URLs**: it
  reports ids, seqs, close codes, error codes and timings only, bounds every wait (10 s a
  step, 30 s for what waits for the worker) and the whole run (180 s).

## Decisions made for this plan

These were settled while writing the plan and verified on minikube. Plan 8A's decisions and
the owner's decisions apply. Do not reopen any of this during execution.

1. **The smoke test uses the WebSocket for everything a client app does.** Requests,
   edits, deletes and reads go over the gateway; contact events, receipts and read positions
   are awaited on the sockets; kicks are awaited as close codes (4003, 4001) rather than on
   Redis; a device not relayed yet is reconnected after 4006 with backoff (250 ms doubling
   to 2 s, so at most about 18 attempts in 30 s, under the `Identify` limit of 30 a minute).
   After each kick the old token is tried again and must be refused: 4003 for the revoked
   device (message-svc refuses it), 4001 for Bob's token from before his reset (the
   password-reset check of Plan 8A).
2. **Refused tokens are signed with auth-svc's own key.** An expired token (two minutes past
   `exp`, beyond the 60 s leeway) and one for another audience, both with auth-svc's key and
   `kid`, so the gateway's `exp` and `aud` checks are what refuses them, not the signature.
   The DEV ONLY smoke Pod (rendered only in dev mode) gets the signing key from the Secret
   through its environment; in exchange it no longer gets the Redis URL, and it never reaches
   message-svc. The Rust tests of Plan 8A cover the other refusals (signature, `kid`,
   algorithm, missing claims, key rotation).
3. **The group request is refused in the smoke test** (`NOT_AVAILABLE`), as the owner
   decided; message-svc's group support stays tested in Rust.
4. **A connection buffers what it is not waiting for.** The gateway pushes contact events,
   receipts and other entries at any time; the smoke test keeps frames it is not waiting for,
   so the order of its waits cannot lose one. An `Error` frame no wait accepts fails the run.
5. **The Messaging token works like the other two.** `PUSH_MESSAGING_TOKEN`: 32 to 256
   visible ASCII characters, different from the Accounts and Directory tokens, compared in
   constant time; without it message-svc warns at start-up and refuses every `Messaging`
   call (`UNAUTHENTICATED`). The gateway requires it, marks the header value sensitive and
   never shows it in `Debug`. Plan 11 adds a NetworkPolicy on top.
6. **Sockets are pinged before the kicks.** A connection the test opened early may have been
   quiet for a while; a `Ping` keeps it clear of the gateway's 75 s idle timeout.

//! The smoke test's WebSocket connections, as a client app holds them: identified with the
//! device's access token, frames sent and awaited in order. Frames that arrive while the
//! test waits for another are kept, so nothing the gateway pushes is lost to the order of
//! the waits.

use std::collections::VecDeque;
use std::time::{Duration, Instant};

use anyhow::{Context, bail};
use futures_util::{SinkExt, StreamExt};
use push_proto::v1::frame::Body;
use push_proto::v1::{self, Identify, Ping, request, response};
use push_proto::{decode_frame, encode_frame};
use tokio::net::TcpStream;
use tokio_tungstenite::tungstenite::Message;
use tokio_tungstenite::tungstenite::client::IntoClientRequest;
use tokio_tungstenite::tungstenite::http::HeaderValue;
use tokio_tungstenite::{MaybeTlsStream, WebSocketStream, connect_async};

use crate::{CONNECT_TIMEOUT, STEP_TIMEOUT, Target, step};

/// How long a closing handshake may take; the test has passed by then.
const CLOSE_TIMEOUT: Duration = Duration::from_secs(2);

/// An identified connection.
pub(crate) struct Conn {
    name: &'static str,
    socket: WebSocketStream<MaybeTlsStream<TcpStream>>,
    /// Frames received while the test waited for something else.
    pending: VecDeque<Body>,
    next_request: u64,
}

/// What became of an `Identify`.
pub(crate) enum Identified {
    Ready(Box<Conn>, v1::Ready),
    /// The gateway closed the connection with this code.
    Closed(u16),
}

/// Connects to the gateway, through the ingress, and identifies with `token`.
pub(crate) async fn identify(
    target: &Target,
    name: &'static str,
    token: &str,
) -> anyhow::Result<Identified> {
    let deadline = Instant::now() + CONNECT_TIMEOUT;
    let mut socket = loop {
        let mut request = target.socket_url.as_str().into_client_request()?;
        if let Some(host) = &target.host {
            request
                .headers_mut()
                .insert("Host", HeaderValue::from_str(host)?);
        }
        match tokio::time::timeout(STEP_TIMEOUT, connect_async(request)).await {
            Ok(Ok((socket, _))) => break socket,
            Ok(Err(error)) if Instant::now() < deadline => {
                step(&format!("{name} cannot connect yet ({error}); retrying"));
            }
            Ok(Err(error)) => {
                return Err(error).context(format!("connect {name} to {}", target.socket_url));
            }
            Err(_) => bail!("connecting {name} timed out"),
        }
        tokio::time::sleep(Duration::from_secs(2)).await;
    };
    let identify = Body::Identify(Identify {
        token: token.to_owned(),
    });
    socket
        .send(Message::Binary(encode_frame(identify).into()))
        .await
        .context("send Identify")?;
    loop {
        let message = tokio::time::timeout(STEP_TIMEOUT, socket.next())
            .await
            .map_err(|_| anyhow::anyhow!("{name}: no answer to Identify within {STEP_TIMEOUT:?}"))?
            .with_context(|| format!("{name}: the connection ended before Ready"))?
            .with_context(|| format!("{name}: the connection failed before Ready"))?;
        match message {
            Message::Binary(bytes) => match decode_frame(&bytes).context("decode a frame")? {
                Body::Ready(ready) => {
                    let conn = Conn {
                        name,
                        socket,
                        pending: VecDeque::new(),
                        next_request: 0,
                    };
                    return Ok(Identified::Ready(Box::new(conn), ready));
                }
                _ => bail!("{name}: expected Ready, got another frame"),
            },
            Message::Close(frame) => {
                return Ok(Identified::Closed(
                    frame.map_or(1005, |frame| frame.code.into()),
                ));
            }
            _ => {}
        }
    }
}

impl Conn {
    pub async fn send(&mut self, body: Body) -> anyhow::Result<()> {
        self.socket
            .send(Message::Binary(encode_frame(body).into()))
            .await
            .with_context(|| format!("{}: send a frame", self.name))
    }

    /// The first frame `wanted` accepts, kept or new, within the step timeout; the others
    /// are kept. An `Error` frame that no wait accepts fails the test.
    pub async fn wait_for(
        &mut self,
        waiting_for: &str,
        wanted: impl Fn(&Body) -> bool,
    ) -> anyhow::Result<Body> {
        if let Some(index) = self.pending.iter().position(&wanted) {
            return Ok(self.pending.remove(index).expect("the index is in range"));
        }
        let deadline = tokio::time::Instant::now() + STEP_TIMEOUT;
        loop {
            let message = tokio::time::timeout_at(deadline, self.socket.next())
                .await
                .map_err(|_| {
                    anyhow::anyhow!("{}: no {waiting_for} within {STEP_TIMEOUT:?}", self.name)
                })?
                .with_context(|| format!("{}: the connection ended", self.name))?
                .with_context(|| format!("{}: the connection failed", self.name))?;
            let body = match message {
                Message::Binary(bytes) => decode_frame(&bytes).context("decode a frame")?,
                Message::Close(frame) => bail!(
                    "{}: closed with {:?} while waiting for {waiting_for}",
                    self.name,
                    frame.map(|frame| u16::from(frame.code))
                ),
                _ => continue,
            };
            if wanted(&body) {
                return Ok(body);
            }
            if let Body::Error(error) = &body {
                bail!(
                    "{}: an error while waiting for {waiting_for}: {:?} ({})",
                    self.name,
                    error.code(),
                    error.message
                );
            }
            self.pending.push_back(body);
        }
    }

    /// Sends a request and returns its answer: the `Response` body, or the `Error`.
    pub async fn ask(
        &mut self,
        body: request::Body,
        what: &str,
    ) -> anyhow::Result<Result<response::Body, v1::Error>> {
        self.next_request += 1;
        let request_id = self.next_request;
        let request = v1::Request {
            request_id,
            body: Some(body),
        };
        self.send(Body::Request(request)).await?;
        let answer = self
            .wait_for(what, |frame| match frame {
                Body::Response(response) => response.request_id == request_id,
                Body::Error(error) => error.request_id == Some(request_id),
                _ => false,
            })
            .await?;
        match answer {
            Body::Response(response) => Ok(Ok(response
                .body
                .with_context(|| format!("{what}: an empty answer"))?)),
            Body::Error(error) => Ok(Err(error)),
            _ => unreachable!("the wait accepts only answers"),
        }
    }

    /// Sends a request that must succeed; its answer.
    pub async fn request(
        &mut self,
        body: request::Body,
        what: &str,
    ) -> anyhow::Result<response::Body> {
        match self.ask(body, what).await? {
            Ok(answer) => Ok(answer),
            Err(error) => bail!("{what}: {:?} ({})", error.code(), error.message),
        }
    }

    /// A `Ping` answered by a `Pong`: the connection is alive and every frame sent before
    /// it was handled (the gateway handles a connection's frames in order).
    pub async fn ping(&mut self) -> anyhow::Result<()> {
        self.send(Body::Ping(Ping {})).await?;
        self.wait_for("a Pong", |frame| matches!(frame, Body::Pong(_)))
            .await?;
        Ok(())
    }

    /// Waits up to `timeout` for the gateway to close the connection; its close code.
    pub async fn closed(&mut self, waiting_for: &str, timeout: Duration) -> anyhow::Result<u16> {
        let deadline = tokio::time::Instant::now() + timeout;
        loop {
            let message = tokio::time::timeout_at(deadline, self.socket.next())
                .await
                .map_err(|_| {
                    anyhow::anyhow!("{}: no {waiting_for} within {timeout:?}", self.name)
                })?;
            match message {
                Some(Ok(Message::Close(frame))) => {
                    return Ok(frame.map_or(1005, |frame| frame.code.into()));
                }
                Some(Ok(_)) => {}
                Some(Err(error)) => {
                    bail!(
                        "{}: the connection failed before {waiting_for}: {error}",
                        self.name
                    )
                }
                None => bail!("{}: the connection ended without {waiting_for}", self.name),
            }
        }
    }

    /// Closes the connection from the client's side.
    pub async fn close(mut self) {
        let _ = tokio::time::timeout(CLOSE_TIMEOUT, self.socket.close(None)).await;
    }

//! claim under test is wrong: one that expired, one for another audience. The smoke test
//! reads the key from the deployment's Secret; it never prints it or the tokens.

use std::time::{SystemTime, UNIX_EPOCH};

use anyhow::Context;
use base64::Engine;
use base64::engine::general_purpose::STANDARD;
use jsonwebtoken::{Algorithm, EncodingKey, Header};
use serde_json::json;
use uuid::Uuid;

/// The PKCS#8 v1 prefix of an Ed25519 private key; the 32-byte seed follows it.
const PKCS8_ED25519_PREFIX: [u8; 16] = [
    0x30, 0x2e, 0x02, 0x01, 0x00, 0x30, 0x05, 0x06, 0x03, 0x2b, 0x65, 0x70, 0x04, 0x22, 0x04, 0x20,
];

/// Signs tokens as auth-svc does, with its key and key id.
pub(crate) struct Forger {
    key: EncodingKey,
    kid: String,
}

impl Forger {
    /// `signing_key` is auth-svc's seed, base64 of 32 bytes; the key id is taken from a
    /// token auth-svc issued, so the gateway finds the key.
    pub fn new(signing_key: &str, issued: &str) -> anyhow::Result<Self> {
        let seed = STANDARD
            .decode(signing_key.trim())
            .ok()
            .filter(|seed| seed.len() == 32)
            .context("the signing key is not base64 of 32 bytes")?;
        let mut der = PKCS8_ED25519_PREFIX.to_vec();
        der.extend_from_slice(&seed);
        let kid = jsonwebtoken::decode_header(issued)
            .context("decode an access token's header")?
            .kid
            .context("auth-svc's access token has no kid")?;
        Ok(Self {
            key: EncodingKey::from_ed_der(&der),
            kid,
        })
    }

    /// A token for `user` on `device` that expired `expired_s` seconds ago (negative: that
    /// expires in as many seconds), for `audience`.
    pub fn token(&self, user: Uuid, device: Uuid, expired_s: i64, audience: &str) -> String {
        let now = SystemTime::now()
            .duration_since(UNIX_EPOCH)
            .map_or(0, |since| since.as_secs() as i64);
        let exp = now - expired_s;
        let claims = json!({
            "sub": user,
            "device_id": device,
            "email_verified": true,
            "exp": exp,
            "iat": exp - 900,
            "jti": Uuid::now_v7(),
            "aud": audience,
        });
        let mut header = Header::new(Algorithm::EdDSA);
        header.kid = Some(self.kid.clone());
        jsonwebtoken::encode(&header, &claims, &self.key)
            .expect("signing with a valid Ed25519 key cannot fail")
    }
}

## Deferred to later plans

- **`socket.rs` identify read loop:** a per-message timeout rather than a single deadline.
- **The wrong-audience check** proves the forged key only indirectly: a token with the
  wrong `aud` is refused, which shows auth-svc's key was accepted only by the refusal's
  reason (4001), not by a separate success case.
- **During an upgrade**, old gateway pods lack the messaging token, so message-svc briefly
  refuses their calls.
- **A NetworkPolicy** so only the gateway reaches `Messaging`, only the worker `Accounts`
  and only auth-svc `Directory` (Plan 11); until then the tokens are the only fence.
- **Rotating the internal tokens and auth-svc's signing key** without a restart (Plan 11,
  Key Vault; the gateway already follows a rotated JWKS by `kid` and keeps a retired key
  for 16 minutes).
- **`x-real-ip` behind an SNAT load balancer** (Plan 11): every client would arrive with
  the balancer's address and share one bucket of the per-IP limits; needs
  `externalTrafficPolicy: Local` or the PROXY protocol.
- **JWKS over https** (Plan 11): the gateway's reqwest is built without TLS; inside the
  cluster the JWKS is fetched over plain http.
- **The smoke test with groups on** (`gateway.groups=true`) and with the SDK instead of raw
  frames (Plan 9; the SDK acks only the highest `seq` during a backlog, as the frame budget
  requires).
- **The 10,000-connection load test**, the drain batches and revisiting the 15-minute
  revocation bound while Redis is down (Plan 11, owner decision 3 of Plan 8A).
