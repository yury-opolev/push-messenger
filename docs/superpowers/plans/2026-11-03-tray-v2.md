# Agent tray v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Glyph tray icon with a status badge, a management window, a bridge-side chat
peek over the control channel, and a slim menu (spec:
`docs/superpowers/specs/2026-11-03-tray-v2-design.md`).

**Architecture:** Logic lives in testable crates in the root workspace
(`push-bridge-control` protocol, `push-bridge` peek ring, `push-tray-core` icon
rasterizer, view models, log tail, menu); the Tauri shell (`apps/push-agent-tray`, its own
workspace) stays thin: commands that call into push-tray-core, a plain HTML/JS page.

**Tech Stack:** Rust 2024 (MSRV 1.85: no let-chains, no newer std APIs), tokio, serde,
Tauri 2 (shell only), plain HTML/CSS/JS.

Conventions for every task: TDD (failing test first), `cargo fmt --all`, `cargo clippy
--workspace --all-targets --locked -- -D warnings`, tests of the touched crates, one or
more commits per task with conventional messages (`feat(tray-core): …`) and the trailer
`Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>`. No new crates in
the root workspace.

### Task 2: push-bridge-control `peek` request, entries and `peek_changed`

**Files:** Modify `crates/push-bridge-control/src/protocol.rs`, `src/lib.rs` (re-exports).

```rust
pub enum Call { Status, RestartBackend, Reconnect, Shutdown, PauseBackend(PauseParams), ResumeBackend, Peek(PeekParams) }
#[derive(Default)] pub struct PeekParams { #[serde(default, skip_serializing_if = "Option::is_none")] pub limit: Option<usize> }
pub const PEEK_CAP: usize = 50; pub const PEEK_DEFAULT: usize = 20; pub const PEEK_TEXT_MAX: usize = 300;
pub fn peek_limit(params: &PeekParams) -> usize; // default 20, clamp 1..=50
pub struct PeekEntry { pub time: i64, pub from: PeekFrom, pub kind: PeekKind, pub text: String,
                       #[serde(default, skip_serializing_if = "Option::is_none")] pub card_state: Option<CardState> }
pub enum PeekFrom { Owner, Agent }               // snake_case
pub enum PeekKind { Text, Reply, Card, Answer, Step, Note }
pub enum CardState { Open, Answered, Declined, Expired }
pub struct PeekResult { pub entries: Vec<PeekEntry> }
pub enum Event { …, PeekChanged }                // {"event":"peek_changed","at":…}
pub const PEEK_DISABLED: &str = "peek_disabled";
```
Wire: `{"id":1,"method":"peek","params":{"limit":5}}`; params optional/null/{}; bad limit
type → `bad_request`. Tests: round trips, clamp, entry JSON spelling, `content_free`
exhaustive classification test (a `match` without wildcard over every `Call` and `Event`
variant, so a new variant fails to compile until classified; only `Peek` carries content).

- [ ] TDD, `cargo test -p push-bridge-control`, fmt, clippy, commit.

Ring API (`peek.rs`):
```rust
pub struct PeekRing { /* VecDeque<Stored>, cap PEEK_CAP */ }
impl PeekRing {
  pub fn owner_text(&mut self, time: i64, text: &str);                 // mask + cap 300
  pub fn owner_answer(&mut self, time: i64, card: ClientMsgId, values: &[String]); // labels from the card's choices; card -> Answered
  pub fn sent(&mut self, time: i64, id: Option<ClientMsgId>, body: &str, text_kind: PeekKind); // Reply or Note
  pub fn edited(&mut self, time: i64, id: ClientMsgId, body: &str);    // replaces that message's entries in place
  pub fn card_state(&mut self, card: ClientMsgId, state: CardState);
  pub fn last(&self, limit: usize) -> Vec<PeekEntry>;                  // oldest first
}
pub fn derive(body: &str, text_kind: PeekKind) -> Vec<Derived>;     // steps, text, card(+choices)
```
`ControlHandle::record(&self, f: impl FnOnce(&mut PeekRing))` no-op when disabled, emits
`Event::PeekChanged` after a change. Hook points: `Core::reply` (Note) / `Core::send_rich`
(Reply), `turns.rs` `apply` edit path (edited), `requests.rs` card send (sent, card) and
`settle` / `expire_requests` / `close_backend_requests` / `cancel_bypass_request` /
`send_failed` (card_state), `conversation.rs` owner text (owner_text, before command
handling) and accepted answers (owner_answer).

Tests: last N kept, masked (`password: hunter2` → `«masked»`), cut to 300 chars, edit
replaces in place, card states, `peek_disabled`, no file is created in the bridge folder
while recording (list the temp dir), and the content-free test: run a Bridge with
TestMessenger/TestBackend and a `ControlHub`, owner says a marker, backend replies the
marker, connect a client, read every event and `status`, assert no marker; `peek` has it.
